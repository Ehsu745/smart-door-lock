**v2.10 對講機階段 1、2（2026-11-14，本地 Claude Code）**：手機聽門口、播放預錄語音。已進 main；Pi 4 同步 v2.10、pytest 通過；**還沒接音效卡實測**（[[Test Queue]] Group E）。規劃與硬體：[[對講機]]

- `intercom.py`：用系統 `arecord` / `aplay`（alsa-utils，不加 Python 套件）。自動找 `arecord -l` 裡名稱含 USB（優先 PnP）的卡 → `plughw:N,0`；`AUDIO_DEVICE` 可指定（被 PipeWire 占用時用 `default`）。`INTERCOM=auto|1|0|sim`，沒有卡 → `make_intercom` 回傳 None，網頁不顯示按鈕
- 收音：mono 16 kHz S16LE，0.1 秒一塊；**有人聽才開 arecord、最後一人離開就關**（`_mic_busy` 鎖確保同時只有一個 arecord）；每個聽眾一個佇列（3 秒），滿了丟最舊的
- 播放：`sounds/*.wav`（16-bit PCM、≤ 30 秒，gitignore），檔名 = 按鈕文字、開頭編號排序；單聲道轉立體聲只放 `INTERCOM_CHANNEL`（預設 left = 門外）；同時只播一段；clip id 不能含 `/`、`\`、開頭 `.`
- 網頁：`GET /api/intercom`（登入）、`GET /audio_feed`（登入；raw PCM、`X-Sample-Rate`；另一個 `StreamRegistry`，規則同影像）、`POST /api/intercom/play`（登入或附 PIN，同 `/api/action`；忙碌 409）；`/api/status.intercom` = `{listen, reply, playing}`（不給聽眾數）；設定頁「系統」多一列對講機
- 事件：`intercom_listen`（同 IP 15 分鐘內只記一次，串流 10 分鐘重連不重複記）、`intercom_reply`；時間軸灰點（`talk`）
- 前端：影像右下角疊「聆聽 / 回覆」（不改 `fitDoor` 的高度分配；矮螢幕 compact 只留圖示）；聆聽 = fetch ReadableStream → Web Audio，緩衝 0.25 秒、超前 1 秒就丟（實測延遲約 0.3 秒）；`AudioContext` 在按鈕 click 裡建立 / resume（iOS 規定），停止時不關 context（PIN 之後重開不是 user gesture）；`navigator.audioSession.type = 'playback'` 讓 iPhone 靜音開關打開也有聲音（Safari 16.4+）；離開門鎖頁 / 背景 / pagehide 就停
- 順便修：PIN 鍵盤的 Enter 沒 `preventDefault`，桌機焦點還在原按鈕時會再按一次那個按鈕（聆聽會無限跳 PIN）
- `test-audio`：找卡 → 錄 5 秒印 RMS / 峰值 → 左、右聲道各播 → `vcgencmd get_throttled`；`tools/make_sounds.py`：Mac `say -v Meijia` + `afconvert` 產生三段預設語音
- 測試 156 → 183（`tests/test_intercom.py`，假麥克風 / 假喇叭）；Playwright Chromium + WebKit、375×548 / 390×664：PIN → 聆聽（AudioContext running、音量條動）→ 回覆（播放中標示、播完解除）→ 停止 / 換頁後 `/api/health` 的 `audio_streams` 歸零；示範模式也有對講（沒有聲音）。使用者 2026-11-14 用手機連 Mac 上的模擬伺服器（真 Flask + `SimMic` 嗶聲 + `SimSpeaker` afplay）實測：手機聽得到嗶聲、回覆從 Mac 喇叭播出
- **待驗證（Pi）**：PipeWire 會不會占住 plughw、USB 卡的 1 聲道錄音、門口 1 m 收音、喇叭最大聲時欠壓、iPhone / LINE 內建瀏覽器的 fetch 串流與 Web Audio

**v2.11 按住說話 + HTTPS（2026-11-18，本地 Claude Code，branch `feat/https-talk`）**：他們要求對講以對話為主 → 手機對門口說話。使用者選了 Pi 自簽憑證（不用 Tailscale）和按住說話（半雙工）。Mac 測過，Pi 5 還沒測（[[Test Queue]] Group H）

- `tls.py`：第一次啟動用系統 `openssl` 產生 `certs/smartlock.crt` / `.key`（gitignore、RSA 2048、825 天＝Apple 上限、SAN 含 `hostname.local` / localhost / 當下 IP；7 天內過期就重產）。沒有新 Python 套件（venv 沒有 `cryptography`）。失敗就退回 http
- 同一個埠 5050 接 http 和 https：`DualServer.finish_request` 在工作執行緒 `MSG_PEEK` 第一個 byte，`0x16` 才包 TLS；http 一律 307 轉 https（舊書籤、QR、直接打 IP 都能用），本機 127.0.0.1 不轉（`curl localhost:5050/api/health` 照用）。不送 HSTS（自簽 + HSTS 會讓瀏覽器不能「仍要前往」）。握手失敗（手機拒絕憑證）只記 debug
- `intercom.py`：`talk_start` → `TalkSession`（token）→ `talk_feed` 每段 16 kHz 單聲道 PCM → 背景執行緒轉立體聲（`INTERCOM_CHANNEL`）寫進 `aplay` stdin（`--buffer-time=400000`，網路抖動 aplay 自己接回）；`_speaker_busy` 鎖讓上一次 aplay 播完尾巴才開下一個（音效卡獨占）。同時只一支手機、和預錄互斥；同一支手機重按會換掉舊的；2 秒沒聲音或超過 `TALK_MAX_SECONDS`（120）自動結束；**說話中 `_mic_loop` 不送給聽眾**（半雙工，不會聽到自己的回音）；結束記 `intercom_talk`「手機對門口說話 N 秒」
- API：`POST /api/intercom/talk`（登入或附 PIN）→ `/api/intercom/talk/<id>`（raw PCM，每段 ≤ 5 秒，否則 413；結束後 410）→ `/end`；`/api/status.intercom` 多 `talk`、`talking`；`MAX_CONTENT_LENGTH` 1 MB
- 前端：影像右下角「聆聽 / 按住說話 / 預錄」（原「回覆」改名預錄），說話鍵最醒目（綠底，按住變紅「說話中」＋音量條；矮螢幕顯示「說話」）。pointerdown → 自動開聆聽（放開就聽得到回答）→ `getUserMedia`（echoCancellation / noiseSuppression / AGC）→ `/talk` → ScriptProcessor 降取樣（區間平均）→ 每 0.15 秒送一段、一次只送一段（順序不亂，網路慢時自動變大段）→ 放開送完最後一段再 `/end`、關麥克風。`audioSession` 說話時 `play-and-record`、之後回 `playback`。不是 HTTPS 時按說話跳說明（Safari / Chrome 開、怎麼略過憑證警告、LINE 不行）；離開門鎖頁 / 背景 / pagehide 就放開
- 測試 188 → 208（`test_intercom.py` 說話 13 個、`test_tls.py` 7 個：憑證產生沿用、同埠 https + http keep-alive、拒絕憑證不影響伺服器、轉址）。Playwright（Chromium 假麥克風）375×548 / 390×664：第一次按跳 PIN → 按住 1.5 秒 → 喇叭端收到約 1.4 秒、只有左聲道、`talking` 為 true、時間軸有事件；WebKit 版面、非 HTTPS 說明、示範模式
- **待驗證（Pi / 手機）**：iPhone Safari 略過憑證警告後能用麥克風、按下到出聲的延遲、iOS 說話後聆聽音量是否變小（錄音模式切回）、Android Chrome、aplay 串流在 Pi 上斷音情況、門外喇叭音量夠不夠
