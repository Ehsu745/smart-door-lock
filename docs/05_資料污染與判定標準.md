# 資料污染與判定標準

> v2.7 起以 SFace 為準（v2.6 前是 LBPH，原理相同、數字不同）。本文的距離 =（1 − cosine 相似度）× 100。

> **一句話**：把照片加進某人的相簿時，標籤錯（別人的照片）會造成污染；標籤對、但照片「不典型」（很不像本人）也可能造成污染。
> 後者不必丟掉，而是**調整判定標準**：比對到這類照片時，要求更嚴格。

---

## 1. 先對齊名詞

| 詞 | 意思 | 本文用法 |
|---|---|---|
| **判定標準**（決策門檻，decision threshold） | 「多像才算是本人」的那條線 | 本文主角 |
| 模型參數（weight） | 機器學習模型內部學出來的數字 | SFace 的參數是預先訓練好、固定不動的；專案從不更動它，本文不談 |
| 距離 | SFace 特徵的（1 − cosine）× 100，「有多不像」，**越小越像** | 例：距離 25 很像，90 幾乎無關 |
| 門檻 | 距離小於門檻才算是這個人 | 專案預設 50（cosine 0.5） |

### 兩種錯誤

門鎖在判斷「這個人是不是 eric」時，虛無假設 H₀ 是「這個人不是 eric」：

| | 實際是 eric | 實際不是 eric |
|---|---|---|
| 系統判定是 eric | 正確 | **型一錯誤＝誤認**（FAR，False Accept Rate） |
| 系統判定不是 eric | **型二錯誤＝誤拒**（FRR，False Reject Rate） | 正確 |

型一、型二會因為「誰是虛無假設」而對調，所以生物辨識領域習慣直接講 **FAR / FRR**，報告裡兩種一起寫最不會被誤解。

> 補充：國際標準 ISO/IEC 19795-1 [4] 把兩組指標分開：
> - **FMR / FNMR**（False Match / Non-Match Rate）：只評估**比對演算法**本身。
> - **FAR / FRR**：評估**整個系統**，還包含「沒拍到臉」這類擷取失敗。
>
> 本文談的是整個門鎖系統，所以用 FAR / FRR；報告裡如果只測人臉比對演算法，應改寫成 FMR / FNMR。

### 判定標準就是在 FAR 和 FRR 之間取捨

```
門檻設得鬆（例如 65）：  eric 幾乎都能進門（FRR 低），但別人也容易被當成 eric（FAR 高）
門檻設得嚴（例如 35）：  別人很難冒充（FAR 低），但 eric 常被擋在門外（FRR 高）
```

選定的那一組（門檻、FAR、FRR）稱為**操作點**（operating point）。報告裡畫一張 DET 或 ROC 曲線、標出選的點，是最標準的呈現方式。

## 2. 我們的人臉辨識怎麼「認人」

專案用 YuNet 找臉、SFace [1][12] 把每張臉轉成 128 維特徵，比對方式像**翻相簿**：


1. 每個人有一本相簿（`faces/` 裡的照片，每張存成一個特徵向量 `face_feats.npz`）。
2. 門口來了一個人，在所有相簿裡找出**最像的那一張**。
3. 那張屬於誰，就判定是誰；但如果最像的那張也有一段差距（距離 ≥ 門檻），就判定為陌生人。

它只看「最像的那一張」，不會把整本相簿平均、也不會投票。所以**相簿裡只要有一張有問題的照片，它就可能成為某個陌生人「最像的那一張」**。

---

## 3. 什麼是資料污染

**加進相簿的照片，讓系統以後更容易判斷錯誤**，就叫資料污染。最危險的是會自我強化的情況：

```
室友 A 被誤認成 eric ──▶ A 的照片存進 eric 的相簿
        ▲                              │
        │                              ▼
  下次更容易把 A 當成 eric ◀── eric 的相簿裡有 A
```

---

## 4. 會造成污染的情況

### 一、標籤正確，但照片本身有害

就算每張照片都經過人工確認、確實是本人，也可能造成污染：

| # | 情況 | 例子 | 會發生什麼 |
|---|---|---|---|
| 1 | **品質差** | 太暗、模糊、過曝、臉太小 | 臉部細節被抹平，變成「誰都有點像」的照片，很多陌生人最像的都是它 → **FAR 上升** |
| 2 | **不典型但清楚** | 戴口罩、墨鏡、大角度側臉、換髮型 | eric 的範圍往那個特徵擴大 → **戴墨鏡的人比較容易被當成 eric**；但 eric 戴墨鏡時比較認得出來（FRR 下降） |
| 3 | **裁切錯誤** | 只框到半張臉、框到背景、框到海報上的臉 | 那張根本不是正常的臉 → FAR 上升 |
| 4 | **翻拍** | 拿 eric 的照片或手機畫面對著鏡頭 | 確實是 eric 的臉，但學進去會讓**拿照片冒充**更容易 |
| 5 | **數量不平衡** | eric 300 張、amy 30 張 | 照片越多，越常剛好是「最像的那一張」→ 判斷會偏向 eric |
| 6 | **條件一面倒** | 新照片全是晚上的紅外線畫面 | 相簿被單一條件主導，其他條件下變差 |
| 7 | **漸進漂移** | 每次只加一點點，單次看都合理 | 累積下來界線慢慢移動，事後很難發現 |

> 第 1、2 種就是「很不像 eric、但確實是 eric」：**對 FRR 有幫助、對 FAR 有傷害**。這種情況不該直接丟掉，而是要調整判定標準（第 5 節）。

### 二、標籤錯誤

人工確認時理論上會排除，但只要開始自動化就會出現：

| # | 情況 | 會發生什麼 |
|---|---|---|
| 8 | **別人的照片標成 eric**（型一錯誤被收進去） | FAR 上升，而且會惡性循環（第 3 節的圖） |
| 9 | **eric 的照片被當成冒充者** | eric 被擋在門外（FRR 上升） |
| 10 | **手勢被偷看** | 有人偷看到 eric 的手勢，拿 eric 的照片加上正確手勢通過；如果系統用「手勢通過」自動判定是本人，就會把冒充的畫面收進 eric 的相簿 |

## 5. 調整判定標準

判定標準可以分三層調整，越往下越細：

### 第一層：全體共用一個門檻（專案原本的做法）

所有人都是「距離 < 50 就算」。簡單，但沒辦法照顧個別狀況。

### 第二層：每個人各自的門檻（v2.7 已完成）

有人常被誤認（例如 eric 跟室友 A 長得像），就只把 eric 的門檻收緊，其他人不受影響：

```
距離：  0 ──── 15 ──────── 32 ──── 42 ─ 45 ──── 49 ── 50 ────▶
              └── eric 本人 ──┘      ▲  └ 室友A ┘    ▲
                              eric 的新門檻 42     原本的門檻 50
```

回報一次「這不是 eric」，系統就知道「冒充者最接近也有 45」，把 eric 的門檻收到 42（再嚴格 3）。eric 本人照樣通過，室友 A 被擋下。

另外還有**冒充者比對**：回報過的那張臉存進 `impostors/`。之後門口的臉只要「比 eric 相簿裡任何一張都更像那張冒充者照片」，就一律當陌生人，不管距離多小。這補足了門檻的盲點：門檻最低只收到 35，再嚴本人會常被擋；比 35 更像 eric 的冒充者要靠這一招擋。

### 第三層：依照片類型的門檻（提案，還沒做）

這一層就是處理「很不像 eric、但確實是 eric」的照片：

- 一般照片（正面、光線正常）：距離 < 50 就算 eric。
- **不典型照片**（暗、側臉、口罩）：距離要 **< 35** 才算 eric。

```
一般照片          ├──────────── 算是 eric ────────────┤ 50
不典型照片        ├──── 算是 eric ────┤ 35
```

**效果**：eric 在暗處、戴口罩時還是有機會被認出來（FRR 不會太高），但陌生人要在暗處冒充 eric，必須「非常像」才行（FAR 受到控制）。

**在 SFace 上的做法**：特徵本來就是一張照片一筆，只要替每筆加一個「類型」標記，比對到哪一筆就套用那一類的門檻，不用分成兩個模型。

## 6. 其他防護方法

調整判定標準之外，還可以從「收不收這張照片」下手：

| 方法 | 做法 | 對應的情況 |
|---|---|---|
| **品質門檻** | 太暗、太糊、臉太小直接不收，請對方重拍 | 1、3 |
| **加入前先驗證** | 用冒充者照片、哨兵錄到的陌生人截圖當測試題；加入新照片後，如果有任何一題變成「被當成 eric」，就不收這張 | 2、6、8 |
| **數量上限＋去除重複** | 每人照片數有上限，太相似的只留一張 | 5、7 |
| **原始照片永遠保留＋可以回到上一版** | 一開始註冊的照片當基準；每次更新前備份 | 7、8 |
| **活體偵測**（進階） | 判斷鏡頭前是真人還是照片 | 4、10 |

---

## 7. 數字的限制

拿 100 個冒充者來測，就算全部擋下，也只能說「FAR 大概不超過 3%」。這是統計上的 rule of three [3]：**全部成功時，失敗率的上限約為 3 ÷ 測試次數**（95% 信心）。

| 測試次數（全部擋下） | 能宣稱的 FAR 上限 |
|---|---|
| 100 | 約 3% |
| 300 | 約 1% |
| 3000 | 約 0.1% |

寫報告時要注意，測試次數不夠，就不能宣稱很小的誤認率。

## 8. 手勢可以當「確認本人」的依據，但有前提

門鎖有兩道驗證（人臉＋手勢），兩者彼此獨立，可以互相印證：

| 情況 | 代表什麼 |
|---|---|
| 人臉通過，**綁定的手勢也正確** | 很可能是本人 |
| 人臉通過，但**手勢比錯或逾時** | 可能是冒充者，值得主人看一眼 |

這種「用第二個獨立線索當作標籤來源」的想法，**借鏡自 co-training** [5]。但嚴格來說不完全一樣：原始的 co-training 是兩個分類器各自學習、互相幫對方標註資料；我們的手勢只是第二道驗證，不會反過來被人臉訓練。報告裡寫「借鏡 co-training 的概念」最準確。

**前提**：手勢沒有被別人知道（第 4 節第 10 種）。所以就算之後要做「手勢通過就自動收照片」，也必須：
- 限制每次加入的數量；
- 先通過第 6 節的「加入前先驗證」；
- 保留原始照片、可以回到上一版。

## 9. 跟強化學習（Reinforcement Learning）有什麼不同

### 9.1 用比喻說明

- **我們的做法（監督式學習）**：像**老師批改考卷**。每一題都告訴你正確答案：「這張是 eric」「這張不是 eric」。
- **強化學習**：像**訓練小狗**。小狗做了一個動作，只得到「給零食」或「不給零食」，沒有人告訴牠正確答案是什麼，牠要自己多試幾次、慢慢摸索哪個動作會有零食。

### 9.2 如果硬把門鎖當成強化學習，會長這樣

| 強化學習的元素 | 套到門鎖上 |
|---|---|
| 狀態（state） | 門口的畫面、距離、手勢 |
| 動作（action） | 開門 / 不開門 |
| 獎勵（reward） | 主人回饋：開對了 +1、開錯（放了冒充者進來）−100、擋錯（擋住主人）−1 |
| 策略（policy） | 「什麼情況下開門」的規則，例如門檻 |

### 9.3 三個關鍵差異：為什麼門鎖不適合用強化學習

| | 監督式學習（我們的做法） | 強化學習 |
|---|---|---|
| **回饋的內容** | 正確答案：「這是誰」 | 好壞分數：「剛才開門對不對」 |
| **每次回饋學到多少** | 多：直接知道這張臉屬於誰 | 少：只知道結果，要自己推敲是哪裡判斷錯（credit assignment，責任歸屬問題） |
| **怎麼取得資料** | 收集、標註照片即可 | 必須**主動嘗試**（探索，exploration）：故意對沒把握的人開門，看結果好不好 |
| **犯錯的代價** | 標錯一張照片，可以刪掉 | 探索時開錯一次門，**小偷就已經進去了**，無法收回 |
| **需要的資料量** | 每人幾十張照片 | 通常要大量嘗試才會收斂 |

最關鍵的是「必須主動嘗試」這一點。強化學習的本質是**從試錯中學習**，但門鎖的錯誤（開錯門）代價太高、無法復原，所以不能拿真實的門來試錯。

### 9.4 容易混淆：資料污染的「惡性循環」不是強化學習

第 3 節的資料污染圖，看起來很像「錯誤被強化」：

```
誤認 ──▶ 照片收進相簿 ──▶ 更容易誤認 ──▶ ……
```

這叫做**正回饋（positive feedback）**或「自我強化」，指的是**錯誤會自己放大**。它跟強化學習（Reinforcement Learning）只是中文都有「強化」兩個字：

| | 資料污染的惡性循環 | 強化學習 |
|---|---|---|
| 是什麼 | 一種**問題**：錯誤被當成答案學進去 | 一種**學習方法**：靠獎勵學習策略 |
| 有沒有獎勵 | 沒有 | 有 |
| 英文 | self-reinforcing / positive feedback loop / confirmation bias | reinforcement learning |

這種循環的學術名稱是 **self-training（自我訓練）的確認偏誤（confirmation bias）** [2]：模型用自己的猜測當答案，猜錯的地方會越學越錯。

### 9.5 強化學習的想法在門鎖上有沒有用處？

有，但只適合拿來「**微調判定標準**」，不適合拿來「學認人」，而且要在安全的範圍內：

- 例如每週根據主人的回饋（誤認幾次、被誤拒幾次）自動微調每人的門檻，這接近強化學習裡最簡單的形式（多臂吃角子老虎機，multi-armed bandit）[6]。
- 但門檻**只能在安全範圍內移動**（例如 35～50），不能為了「試試看」而放寬到會讓冒充者進門的程度。
- 目前的做法（回報一次就收緊）其實就是這個想法的保守版本：**只往安全的方向調**。

### 9.6 我們做的到底叫什麼

| 名稱 | 意思 | 在專案裡 |
|---|---|---|
| **監督式學習** | 用有正確答案的資料訓練 | 主人拍照、註冊名字 |
| **人工標註**（human-in-the-loop） | 由人提供或確認正確答案 | 回報「這不是 某某」、取消回報 |
| **主動學習**（active learning） | 只把沒把握的樣本拿去問人 | 時間軸上的人臉小圖讓主人判斷 |
| **借鏡 co-training** [5] | 用第二個獨立線索提供標籤 | 手勢通過＝人臉照片是本人的佐證 |
| **線上學習**（online learning） | 系統運作中持續更新 | 冒充者特徵即時加入、門檻即時收緊（都不用重新啟動） |

寫報告或履歷時，用這些詞比說「強化學習」準確。

## 10. 「把辨識失敗的樣本拿去重新訓練」叫什麼

常見的問題：AI 影像辨識時，為什麼不把**辨識失敗、但其實是正確物件**的東西收成一個資料集，再拿去重新訓練？

這個做法**存在，也很常用**，但它**不是強化學習**，而是監督式學習的一種技巧。對應的名稱：

| 名稱 | 意思 | 跟這個問題的關係 |
|---|---|---|
| **困難樣本挖掘**（hard example mining） | 專門找出模型答錯、或沒把握的樣本，加重訓練 | **最貼切的名稱**。物件偵測的經典做法是 OHEM [7] |
| **資料飛輪**（data engine / data flywheel） | 部署後收集失敗案例 → 人工標註 → 加回訓練集 → 再部署，週而復始 | 業界對整個流程的稱呼 |
| **主動學習**（active learning） | 只挑模型沒把握的樣本拿去問人 | 收集失敗案例的那一步 |
| **Boosting**（例如 AdaBoost [8]） | 每一輪**提高答錯樣本的權重**，下一個模型專攻這些題目 | 這裡的「權重」真的是用來加重錯題的影響力 |

### 依錯誤類型細分

| 失敗的樣子 | 名稱 | 該放哪裡 | 在門鎖上 |
|---|---|---|---|
| 是正確物件，卻沒認出來（漏認、型二錯誤） | **hard positive** | 加進**正確的類別** | eric 在暗處被拒，經人確認是 eric → 加進 eric 的相簿（注意第 4 節第 1、2 種，搭配第 5 節第三層門檻） |
| 不是目標，卻被認成目標（誤認、型一錯誤） | **hard negative** | 當成**反例** | 室友被認成 eric → 冒充者比對（v2.7 已實作） |

### 為什麼不是強化學習

兩者都是「從錯誤中學習」，所以容易被混為一談，但：
- 困難樣本挖掘：每個失敗樣本**都有人標註正確答案**，是監督式學習。
- 強化學習：**沒有正確答案**，只有「動作好不好」的獎勵，而且要靠自己試錯（第 9 節）。

> 前提跟本文的主軸一樣：**失敗樣本一定要先經過可靠的標註**。如果直接拿模型自己的判斷當答案，困難樣本挖掘就會退化成第 3 節的資料污染。

## 11. 強化學習也有資料污染的風險嗎

有，而且某些方面**比監督式學習更嚴重**。

原因：強化學習的**資料是模型自己的行為產生的**。策略決定它會看到什麼資料，資料又反過來決定策略，形成封閉迴圈。

| 風險 | 說明 | 出處 |
|---|---|---|
| **獎勵投毒**（reward poisoning） | 攻擊者竄改獎勵訊號，引導模型學出攻擊者想要的策略 | [9] |
| **退化回饋迴圈**（degenerate feedback loop） | 推薦系統只推它以為你喜歡的，你只能點它推的，資料越來越偏，最後困在小圈圈裡（同溫層） | [10] |
| **獎勵模型過度最佳化** | RLHF 的獎勵模型是從人類標註學來的，本身有誤差；策略越努力迎合它，越會鑽它的漏洞，真實品質反而下降 | [11] |
| **獎勵設計錯誤**（reward hacking） | 獎勵沒寫好，模型找到「拿高分但不是你要的」的捷徑 | [6] |

### 跟門鎖的資料污染比較

| | 監督式學習的自我訓練（門鎖的情況） | 強化學習 |
|---|---|---|
| 污染從哪來 | 錯的**標籤**被學進去 | 錯的**獎勵**，或策略自己造成的**資料偏差** |
| 惡性循環的樣子 | 誤認 → 照片收進相簿 → 更容易誤認 | 偏好某個動作 → 只收到那個動作的回饋 → 更偏好它 |
| 共通的根源 | **系統的輸出會回頭變成自己的訓練資料**，錯誤就會自我放大 | 同左 |

**一句話**：只要系統的輸出會回頭變成自己的訓練資料，不管是監督式還是強化學習，都有污染和惡性循環的風險；強化學習因為資料本來就是自己產生的，這個問題是內建的。

## 一頁總結

| 問題 | 答案 |
|---|---|
| 什麼是資料污染？ | 加進相簿的照片讓系統以後更容易判斷錯誤 |
| 只有標籤錯才會污染嗎？ | 不是。標籤對、但品質差或不典型的照片也會讓 FAR 上升 |
| 「很不像 eric 但確實是 eric」的照片怎麼辦？ | 不必丟掉，**調整判定標準**：比對到這類照片時要求更嚴格（第三層門檻） |
| 判定標準在調什麼？ | FAR 和 FRR 之間的取捨，也就是操作點 |
| 目前做到哪？ | 每人門檻、冒充者比對、回報與取消回報；主人相簿不會自動加入照片 |
| 跟強化學習的差別？ | 我們用正確答案（誰是誰）學習；強化學習靠獎勵和試錯，門鎖不能拿開門來試錯 |
| 資料污染的惡性循環是強化學習嗎？ | 不是。那是自我訓練的確認偏誤（正回饋），只是中文都有「強化」 |
| 把辨識失敗的樣本拿去重新訓練叫什麼？ | 困難樣本挖掘（hard example mining）；漏認的是 hard positive、誤認的是 hard negative。屬於監督式學習 |
| 強化學習會有資料污染嗎？ | 會，而且是內建的：獎勵投毒、退化回饋迴圈、獎勵模型過度最佳化 |
