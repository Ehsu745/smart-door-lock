# 智慧門鎖：優化規劃

> 狀態：目前要進行的項目
> 基準版本：`door_pi_gesture/app.py`（單檔，約 1000 行，人臉＋手勢＋QR＋guest 通知）

---

## 1. 程式模組化

**原則**：一個檔案只負責一件事。有狀態的東西用類別，單純的計算用函式，不必全部改成物件導向。

### 目錄結構
```
door_lock/
├── __main__.py      # 指令列入口：python -m door_lock run / capture / train
├── config.py        # 設定集中（dataclass，從環境變數讀取）
├── camera.py        # Camera、RpicamCamera
├── face.py          # 人臉偵測、LBPH、capture、train
├── gesture.py       # GestureDetector、classify_landmarks
├── arduino.py       # Arduino、FakeArduino
├── door.py          # DoorSystem 狀態機
├── sentinel.py      # 哨兵、錄影（新功能）
├── notifier.py      # 通知（LINE 等，新功能）
├── storage.py       # SQLite 事件紀錄
├── display.py       # 預覽視窗、QR code
└── web/
    ├── server.py
    ├── templates/index.html
    └── static/
```

### 關鍵做法
- **依賴注入**：寫成 `DoorSystem(camera, arduino, notifier)`，由外部傳入相機、Arduino、通知，測試時就能換成假的。
- **事件匯流排**：狀態機只負責發出事件（`unlocked`、`stranger_detected`、`guest_detected`），哨兵、通知、網頁、紀錄各自訂閱。之後加功能都不用改狀態機。
- **用 `logging` 取代 `print`**，可以分等級，也能輸出到檔案。
- **加上 type hints**，並用 pytest 測試狀態機，至少涵蓋：guest 不開鎖、手勢逾時、開鎖後不重複開。

### 重構步驟
1. 用 git 管理，每拆完一個模組就 commit
2. **重構期間不加新功能**，拆完先確認行為和原本完全一樣
3. 拆分順序：`config` → `camera`／`arduino` → `face`／`gesture` → `door` → `web`（HTML 移到 `templates/`）→ 新功能

## 2. 哨兵功能

### 觸發條件
| 條件 | 值 |
|---|---|
| 陌生人連續出現 | ≥ 5 秒 |
| 這段期間沒有認出 master | 必要條件 |
| 兩次通知最短間隔 | 5 分鐘 |
| 人臉大小 | ≥ `MIN_FACE` |

### 紀錄
- **環形緩衝區**：記憶體保留最近 5 秒的畫面，觸發時連同觸發前的畫面一起寫入影片。
- 陌生人離開 5 秒後停止錄影，單段最長 60 秒。
- 影片用 `cv2.VideoWriter`，存成 `.mp4`（`mp4v`）或 `.avi`（`MJPG`）。
- 另存一張最清楚的截圖。
- 文字紀錄存在 **SQLite**，欄位：時間、持續秒數、影片路徑、截圖路徑、最小 LBPH 距離、是否已通知。
- 設定保留上限（例如 7 天或 2 GB），超過自動刪除最舊的。
- 在控制頁加一個「哨兵紀錄」頁面。

### 通知：LINE Messaging API
- **費用**：輕用量方案 NT$0，每月 200 則推播，測試完全夠用。Reply API（使用者先發訊息、Bot 回覆）免費。
- **申請**：LINE Developers → Messaging API channel → 取得 Channel access token → 從 Basic settings 取得自己的 user ID → 把官方帳號加為好友。
- **呼叫**：`POST https://api.line.me/v2/bot/message/push`，header 帶 `Bearer <token>`，body 帶 `to` 和 `messages`。
- **限制**：圖片和影片只接受公開的 HTTPS 網址，不能直接上傳檔案。
- **做法**：先只推送文字，錄影存在 Pi 上，從控制頁查看。之後需要附圖再評估 Cloudflare Tunnel 或另加 Telegram。
- token 和 user ID 放環境變數，**不要寫進程式，也不要推上 GitHub**。
- 寫成 `Notifier` 介面的一個實作（`LineNotifier`），換通知管道時不用改哨兵的程式。
- 通知內容不放開鎖連結。

## 3. 效能與執行方式

### 背景執行（優先）
- 用 **systemd 服務**：開機自動啟動、當掉自動重啟、不佔用終端機。
- 這只改變執行方式，不影響效能。

### 事件驅動（省資源）
目前每一幀都跑人臉辨識，沒人時 CPU 也在空轉。

| 做法 | 閒置 CPU | 需要硬體 |
|---|---|---|
| 軟體移動偵測：低解析度比對畫面差異，有變化才跑辨識 | 低 | 不用 |
| PIR／毫米波 + GPIO 中斷（`gpiozero` 回呼） | 接近 0 | 需要 |

| 優點 | 缺點 |
|---|---|
| 閒置時 CPU、溫度、耗電明顯下降 | PIR 會誤觸發，也有死角 |
| 適合搭配哨兵的事件架構 | 關掉相機的話，喚醒會有延遲 |
| 可以量化前後差異，放進報告 | 狀態變多，邏輯更複雜 |

**建議**：先做 systemd，再做軟體移動偵測。改之前和改之後都用 `htop`、`vcgencmd measure_temp` 量一次。

## 4. 已知問題與對策

| 問題 | 對策 |
|---|---|
| 同一人在 master 和 Unknown 之間跳動 | 在門口實際位置和光線下重拍，距離值穩定在 50 以下再上線 |
| 背景誤判成人臉，導致無法重新允許自動開鎖 | 改成以「沒有認得的人」持續 3 秒為重新允許條件（已有修改方案，必要時再套用） |
| NoIR 相機畫面偏紫 | 不影響辨識；手勢偵測率若不夠，改用 USB 相機（`CAMERA=usb`） |
| 網頁無登入 | 一律設定 `CONTROL_PIN` |
| SD 卡損壞風險 | 用 `sudo poweroff` 關機、改用 5V/5A 電源，長期可改用 USB SSD |
