# 居家助理：未來規劃

> 狀態：構想階段，尚未實作
> 用途：整合人臉門鎖、手勢辨識、物件辨識，未來加入 LLM 與語音

---

## 1. 整體架構

| 模組 | 角色 | 來源 |
|---|---|---|
| 人臉辨識 | 誰（家人／訪客／陌生人） | 智慧門鎖 |
| 手勢辨識 | 免語音控制、確認操作 | 簡報手勢控制器 |
| 物件辨識（YOLO） | 什麼東西、在哪裡 | 金屬零件辨識，改訓練成家中物品 |
| 門鎖／繼電器 | 執行動作 | 智慧門鎖 |
| LLM | 理解自然語言、決定呼叫哪個功能 | 未來加入 |

- **模組之間用 MQTT（Mosquitto）溝通**，每個模組都能獨立開發、獨立重啟。
- **可接 Home Assistant**，直接使用現成的儀表板、自動化規則和手機 App。
- **LLM 透過工具呼叫（tool calling）使用各模組**，例如 `find_object()`、`events_today()`、`unlock_door()`。
- **安全底線：LLM 不能自行決定開鎖**，必須經過人臉＋手勢或 PIN 驗證。

**推進順序**：程式模組化 → 加 MQTT → 物件辨識模組 → 儀表板／Home Assistant → 語音 → LLM

## 2. 手勢觸發（避免一直運算、避免誤觸發）

主流做法是**分層喚醒**：先用便宜的方式偵測，確定有人或有手，才啟動昂貴的辨識。

| 層級 | 方式 | 範例 |
|---|---|---|
| 硬體感測（真正的中斷） | 感測器的 INT 腳位接 GPIO | PAJ7620（9 種手勢）、APDS-9960、毫米波雷達 HLK-LD2410 |
| 存在偵測 | 偵測到有人才開相機辨識 | PIR、毫米波 |
| 軟體分層 | 移動偵測 → 手掌偵測 → 關鍵點 → 分類 | MediaPipe 內建 |
| 喚醒手勢 | 先比特定手勢才進入指令模式 | 張開手掌 1 秒 |

**建議流程**：毫米波／PIR 偵測到人 → 開啟相機 → 張開手掌 1 秒喚醒 → 5 秒內的手勢才算指令 → 冷卻時間

## 3. Pi 5 跑 LLM 的效能

實測數據（Pi 5、CPU、Ollama、4-bit 量化）：

| 模型 | 速度（tokens/秒） | 記憶體 |
|---|---|---|
| Gemma 3 1B | ~11.5 | ~1.4 GB |
| Qwen2.5 1.5B | ~10 | ~1.8 GB |
| Qwen2.5 3B | ~5.2 | ~3.0 GB |
| Llama 3.2 3B | ~4.7 | ~4.7 GB |

**結論**
- **Pi 5 4GB 實際只能跑 1–1.5B 模型**，因為還要跑視覺模型。中文選 Qwen2.5 系列。
- 小模型適合處理簡單問答和工具呼叫，推理能力弱。
- 完整語音流程（語音轉文字 → LLM → 語音合成）在 Pi 上一次約 5–10 秒。
- **AI HAT+ 2**（Hailo-10H、40 TOPS、板上 8GB、約 US$130）可以分擔運算，但支援的模型一樣只有 1–1.5B，能力不會變強。

**建議採混合架構**
- **Pi 本地**：喚醒詞（openWakeWord）、語音轉文字（Whisper）、語音合成（Piper）、固定指令
- **LLM 放在別處**：雲端 API，或家中有 GPU 的電腦跑 Ollama，Pi 透過區網呼叫

## 4. 記憶設計

LLM 每次對話都會「失憶」。所謂記憶，是程式在對話前把相關資料找出來放進提示詞。

| 層級 | 內容 | 儲存 | 使用方式 |
|---|---|---|---|
| 短期 | 本次對話 | 記憶體，過長就摘要 | 每次附上 |
| 結構化 | 偏好、物品位置、門鎖事件 | **SQLite** | LLM 用工具查詢 |
| 語意 | 對話摘要、筆記 | SQLite + `sqlite-vec`（向量） | 相似度搜尋（RAG） |

**設計重點**
- **用人臉辨識決定載入誰的記憶**，這是純語音助理做不到的優勢。
- **物品位置交給 YOLO 寫入資料庫**，LLM 只負責查詢，不靠 LLM 自己記，才不會亂掰。
- 使用者說「記住……」時，LLM 呼叫 `save_memory()` 寫入。
- 提供頁面讓使用者查看、刪除記憶（隱私與除錯）。
- **起步先只用 SQLite**，不夠用時再加向量搜尋。

## 5. 主流語音助理（2026）

| 助理 | 現況 |
|---|---|
| Alexa+（Amazon） | 生成式 AI 版已上線，可連續對話、處理多步驟任務 |
| Gemini for Home（Google） | 取代 Google Assistant，能理解所在房間的脈絡 |
| Siri（Apple） | 大型語言模型版本尚未推出，預計 2026 年稍晚 |
| Home Assistant Assist | 開源，可完全本地執行，也可接本地或雲端 LLM |

**共通功能**：喚醒詞、連續對話、智慧家庭控制（Matter）、情境自動化、多使用者辨識（聲紋，新裝置加入人臉）、計時器／提醒／行事曆、影音控制、門鈴與攝影機整合（認得熟面孔）、生成式 AI 對話

**本專題的差異化**：本地運算與隱私（影像不上雲）、視覺互動（手勢控制、找東西）
